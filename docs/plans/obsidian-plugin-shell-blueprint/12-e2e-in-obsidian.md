# Task 12 · End to end in real Obsidian

Phase A. Needs: Task 11.

**Goal.** A suite that builds the plugin and runs it in the real Obsidian app, so lifecycle, theme, pop-out, view state, language and network behaviour are proven where users run them. It is not part of the gate (it needs a display and a download); CI runs it as its own job (Task 21). It also gives the harness its real host values.

## Files

Create: `tests/e2e/wdio.conf.mts`, `tests/e2e/tsconfig.json`, `tests/e2e/support.ts`, `tests/e2e/vaults/basic/` (a small vault of plain Markdown notes and no `.obsidian/` folder: three notes, one in a subfolder), `tests/e2e/specs/{lifecycle,settings-and-theme,external-settings,popout,navigation,language,no-network}.e2e.ts`. Modify: `tsconfig.json` (reference `tests/e2e/tsconfig.json`), `package.json` (`typecheck` appends `&& tsc -p tests/e2e/tsconfig.json`; script `test:e2e`), `eslint.config.mjs` (`tests/e2e/tsconfig.json` in the TypeScript projects), `configs/fallow.config.mjs` (`ignoreDependencies` gains `wdio-obsidian-reporter`, `@wdio/local-runner`, `@wdio/mocha-framework`), `harness/fake-host.css` (step 6).

Install (`devDependencies`): `wdio-obsidian-service`, `wdio-obsidian-reporter`, `@wdio/cli`, `@wdio/local-runner`, `@wdio/mocha-framework`, `@wdio/globals`, `mocha`, `@types/mocha`.

## Steps

- [ ] **0. TypeScript project** (`tests/e2e/tsconfig.json`): extends `../../configs/tsconfig.base.json`, `lib: ["ES2023", "DOM", "DOM.Iterable"]`, `types: ["node", "@wdio/globals/types", "@wdio/mocha-framework", "wdio-obsidian-service"]`, includes `**/*.ts` and `**/*.mts`. `configs/tsconfig.app.json` already excludes `tests/e2e/**`.
- [ ] **1. Config** (`tests/e2e/wdio.conf.mts`): `rootDir` the repository root; `cacheDir` `.obsidian-cache` (git-ignored; about 1.3 GB unpacked; never commit or share it: Obsidian's terms forbid redistribution; in a git worktree a symlink to the main checkout's cache avoids a second download); `parseObsidianVersions(env.OBSIDIAN_VERSIONS ?? "latest/latest", { cacheDir })` (latest app on the latest installer; `earliest/earliest` is `minAppVersion` on the oldest installer it accepts); with `CI` set, print one line `obsidian-cache-key: <versions>` for the workflow's cache key; `framework: "mocha"`, `specs: ["./tests/e2e/specs/**/*.e2e.ts"]`, `maxInstances` from `WDIO_MAX_INSTANCES` (default 2); per capability `browserName: "obsidian"` with `wdio:obsidianOptions: { appVersion, installerVersion, plugins: ["dist"], vault: "tests/e2e/vaults/basic" }` (Task 13 adds the probe plugin) and `goog:chromeOptions: { args: ["--lang=<test-language>"] }` (without a stored choice Obsidian takes its language from Chromium's locale, which is `en-US` in CI and containers); `services: ["obsidian"]`, `reporters: ["obsidian"]`, `mochaOpts: { ui: "bdd", timeout: 60_000 }`, `waitforInterval: 250`, `waitforTimeout: 5_000`, `logLevel: "warn"`, `outputDir: reports/e2e`, `injectGlobals: false`. Script `test:e2e`: `npm run build && wdio run tests/e2e/wdio.conf.mts` (Tasks 13 and 16 insert `build:probe` and `vault:reference`).
- [ ] **2. Support** (`tests/e2e/support.ts`): constants `PLUGIN_ID`, `VIEW_TYPE`, `ROOT` (`.<plugin-id>-root`), `DATA_FILE` (`.obsidian/plugins/<plugin-id>/data.json`); `installConsoleSpy()` (records `console.error`, `console.warn`, uncaught errors and unhandled rejections in the main window, and ignores only Chromium's `ResizeObserver loop` notification, which fires when a pop-out opens or resizes); `pluginProblems()` (what the spy saw that names the plugin, `[Vue` or `nuxt`, plus every uncaught error); `openView()` = `browser.executeObsidianCommand("<plugin-id>:open-view")`; helpers for `data.json`, plugin reload, the settings tab's content and the light/dark switch. `browser.executeObsidian(({ app, obsidian }, ...args) => …)` runs code inside Obsidian; the function is serialised, so pass values as arguments; closures and module-level helpers do not work there (the oxlint override of Task 02).
- [ ] **3. Waiting** (L36): every wait is on an observable condition (`browser.waitUntil`, `expect(...).toHaveText`, a value read through `executeObsidian`), never a fixed pause before an effect. A check that something did **not** happen waits for a positive sign after it first. Wait for a list or a lazily loaded part to show what a click needs before clicking (L9, L10).
- [ ] **4. Specs** (each ends with `expect(await pluginProblems()).toEqual([])`; the spy is installed after the first load, so the disable/enable cycles provide load coverage). Elements are found by the `data-testid` values of Task 10 under `ROOT`:
  - `lifecycle.e2e.ts`: the view opens on the start route; `open-view` reveals instead of duplicating; two tabs, one closed, the other works; the ribbon entry exactly once in `app.workspace.leftRibbon.items` after each load and after a ribbon re-render; three disable/enable cycles leave no view behind.
  - `settings-and-theme.e2e.ts`: the native tab holds only the log level, and a level chosen there is saved to `data.json`; a light/dark switch reaches the open surface with Obsidian's colours; a newer `data.json` shows read-only (dropdown disabled, the read-only row, a notice) and is never overwritten.
  - `external-settings.e2e.ts`: `data.json` changed outside Obsidian is followed by the tab and the open view; a newer-version file switches the tab to read-only and is never rewritten.
  - `popout.e2e.ts`: the view moved to a pop-out window: surface, portal and an open dialog in the pop-out's document and none in the main one; a theme switch there; a clean close.
  - `navigation.e2e.ts`: the route in the leaf's view state and in the saved `workspace.json`; broken and unknown states fall back to the start route; a note opened like a file-explorer click (`getLeaf(false).openFile`) while the plugin tab is active goes to another tab; the view restored on its route after Obsidian restarts, with an empty history. **Back and forward**: the app has no second route of its own yet, so the spec builds a second view with a test-only route, inside Obsidian, through `executeObsidian`: it takes the open view of `VIEW_TYPE` and reads its fields `runtime`, `surfaces` and `definition` (Task 10 step 8); it builds a definition `{ ...definition, decode, equals, screen, menu }` whose `decode` also accepts `{ name: "probe" }`, whose `screen` gives `undefined` for it (so the frame shows not-found) and whose `menu` adds an entry labelled `Probe` for it; it constructs `new (view.constructor)(leaf, runtime, surfaces, probeDefinition)` on `app.workspace.getLeaf("tab")`, sets `view.containerEl.dataset.e2e = "probe"` and calls `leaf.open(view)`. The spec then works inside `[data-e2e=probe] <ROOT>`: no `frame-history` at first; the `Probe` entry in `frame-navigation` shows `not-found`; its back button returns to the start screen; the frame's back control (found by its accessible name from the catalog) goes to `probe` and again to the start, where it says `aria-disabled="true"`, stays enabled and keeps the focus; forward goes to `probe`. At the end it detaches every leaf whose view carries `data-e2e=probe`.
  - `language.e2e.ts`: `<test-language>` from the start; switched the way Obsidian's setting does it (`localStorage` key `language`, then a plugin reload): view, ribbon title (unchanged), command and setting names and notices in the other language. Only this spec and at most two others may assert literal sentences; the rest read texts from the typed catalog.
  - `no-network.e2e.ts`: with the view and a dialog open, no entry of `performance.getEntriesByType("resource")` points to `http`, `https`, `ws` or `wss`. Discriminating check: an icon not in `SHELL_ICONS` makes it fail without `keepIconsOffline` (a request to `api.iconify.design`) and pass with it.
  Task 13 adds `events.e2e.ts` with the file events.
- [ ] **5. Running.** Linux without a display: `xvfb-run -a npm run test:e2e`. Windows and macOS need nothing extra. The first run downloads Obsidian. Each spec file gets a fresh Obsidian with a copy of `tests/e2e/vaults/basic` and `dist/` installed.
- [ ] **6. The fake host's values** (L26). Write a throwaway spec `tests/e2e/specs/_host-values.e2e.ts` that, in light and then in dark, prints through `executeObsidian` the computed value on `document.body` of every variable `harness/fake-host.css` declares, and the computed styles of the elements its base rules stand for (a `button`, an `input[type=text]`, `h1`–`h6`, `ul`/`ol` with `li`, `p`). Run it once, paste the values into `harness/fake-host.css` in place of the placeholders, replace the placeholder comment with one naming the Obsidian version the values were read from (`Obsidian 1.15.1, default theme, computed on body`), and delete the spec. Check: `node -e "process.exit(require('fs').readFileSync('harness/fake-host.css','utf8').includes('PLACEHOLDER')?1:0)"` exits 0, and `npm run build:ui` exits 0.
