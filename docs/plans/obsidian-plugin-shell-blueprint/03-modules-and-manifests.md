# Task 03 · Modules and manifests

Phase A. Needs: Task 02.

**Goal.** The module structure exists before the second concern does (L2): every layer is cut into module folders, a module registers itself with a plain-data manifest, the application lists the manifests once in `APP_MODULES`, and ESLint and fallow read their module lists from that one list (L3, L15). Only the `shell` module exists after this task; `notes` comes in Task 13, the tracer in Task 18.

## Files

Create: `src/application/module.ts`, `src/application/modules.ts`, `src/application/shell/{index,module}.ts`, `src/application/shell/i18n/{catalog,de,en}.ts` (one file per language of `<languages>`; Task 05 fills them), `src/domain/shell/index.ts`, `scripts/modules.mjs`, `configs/fallow.config.mjs`, `scripts/fallow-config.mjs`, `configs/fallow.json` (generated), `tests/unit/scripts/modules.test.ts`, `tests/unit/scripts/fallow-config.test.ts`, `tests/unit/application/modules.test.ts`, `tests/unit/application/module.test.ts`. Modify: `eslint.config.mjs`, `package.json`, `scripts/verify.mjs` (add `analyze`).

Install: `fallow`.

## The rules this task enforces

- **Layers × modules.** Module folders: `src/domain/<module>/`, `src/application/<module>/`, `src/infrastructure/obsidian/<module>/`, `src/infrastructure/memory/<module>/` (in-memory adapters for tests and the harness, Task 06), `src/presentation/<module>/`. A module has a folder only in the layers where it has code; a feature that adds no adapter has no infrastructure folder.
- **Public face.** Outside a module folder, code imports it only through its `index.ts` (`../shell`, never `../shell/ports`), also the same module from another layer. Second entries, each for one kind of caller: `presentation/shell/host.ts` (Vue-free, for plugin-load code, Task 09), `application/notes/adapter.ts` (the `NoteStore` adapters' kit, for `src/infrastructure/**` only, Task 13), and each presentation module's `screens.ts` (for `src/presentation/*.ts` only, Task 10). Tests may import a module's files directly.
- **Direction.** feature → `notes` → `shell`. `shell` imports no other module; `notes` imports only `shell`; features may import each other's index, acyclically (fallow's cycle check).
- **Composition files.** The files at a layer's root only compose module parts: in application `module.ts`, `modules.ts`, `errors.ts` (`AppError`), `events.ts` (`AppEvent`), `app-services.ts`, `app-services-layer.ts`, `messages.ts`, `user-messages.ts` (`describeError`), `routes.ts`, `note-types.ts`, `commands.ts`; in infrastructure `obsidian/app-layer.ts`, `runtime.ts`, `logging/`; in presentation `app-surface.ts`. Each arrives in the task that needs it.
- **Type-only edges to the root.** `EventBus` and `Messages` (shell) carry the composed `AppEvent` and `Catalog`, so `src/application/shell/` imports them from the root as types only; runtime imports go the other way only.

## Steps

- [ ] **1. The manifest shape** (`src/application/module.ts`). Test first in `tests/unit/application/module.test.ts`: two stub manifests give `catalogOf(modules, language)` with one key per module name, and `describerOf(modules)` hands an error to the module whose `tags` name its `_tag`, with that module's part of the catalog. Then write:
  - `type ErrorTags<E extends { _tag: string }> = { readonly [Tag in E["_tag"]]: true }`: typecheck fails while a tag is missing or extra.
  - `type ModuleManifest<…>` with `name` (the folder name in every layer, and the module's key in `Catalog`), `catalog` (one entry per language, one type), and the optional parts `errors: { tags, describe(error, messages): UserMessage }`, `commands` (Task 05), `services` (Task 06), `routes` and `sections: { id, order }[]` (Task 10), `noteTypes` (Task 13). A part a module does not have is left out.
  - `defineModule(manifest)`, generic with `const Name` and defaults of `never`, returning the manifest unchanged so every type is inferred.
  - The derivations: `CatalogOf<M>`, `ErrorOf<M>` (the union of the describers' error parameters), `catalogOf`, `describerOf`; later tasks add `commandsOf`, `servicesLayerOf`/`ServicesOf`, `sectionsOf`/`SectionOf`, `routeSchemasOf`/`RouteOf`, `noteTypesOf`. The file imports no module at runtime (types only).
- [ ] **2. The shell's manifest.** `src/application/shell/module.ts`: `export const shellModule = defineModule({ name: "shell", catalog: { … } })`, exported from `src/application/shell/index.ts`. Task 05 adds its errors and commands. `module.ts` needs two shell types now: `Language` (the union of `<languages>`, in `src/application/shell/i18n/catalog.ts`) and `UserMessage` (in `src/application/shell/user-messages.ts`; its shape is in Task 05 step 10). Create both here with the catalog type holding one entry (the shell's display name); Task 05 fills them.
- [ ] **3. The module list.** `src/application/modules.ts`: `export const APP_MODULES = [shellModule] as const;`, `type AppModule`, `type AppModuleName`. Each element is an identifier imported from `./<module>`; the order is load order with the core modules first.
- [ ] **4. Reading the list without running it** (`scripts/modules.mjs`). Tests first (`tests/unit/scripts/modules.test.ts`): a list text gives its names in order; an element not imported from `./<folder>` fails naming the element; a list that does not start with the core modules fails. Then: `MODULE_LIST = "src/application/modules.ts"`, `CORE_MODULES = ["shell"]` (Task 13 makes it `["shell", "notes"]`), `parseModuleNames(text)` with the `typescript` compiler API (`ts.createSourceFile`, the `APP_MODULES` array literal, each identifier mapped to the folder of its import), and `readModules(text?)` returning `{ all, core, features }`.
- [ ] **5. ESLint module rules** (`eslint.config.mjs`, after the oxlint block, built from `readModules()`; ADR 0006):
  - `pastIndexWith(extra)`: per module, the pattern `(^|/)<module>/(?!(index|<second entry>|<extra>)$)` with the message `Import module <module> only through its index.ts`; second entries `{ shell: "host", notes: "adapter" }`; plus a pattern refusing `shell/host` outside `presentation/`.
  - For `src/**/*.{ts,vue}`: `pastIndex`, the kit rule (Task 13) and `testOnly` (`(^|/)memory(/|$)`, "the in-memory adapters are for tests and the harness only"); for `src/infrastructure/**/*.ts` the same with the infrastructure's kit rule; for `src/presentation/*.ts` `pastIndexWith(["screens"])`.
  - `vueFreeAtLoad(files, regex)` with `@typescript-eslint/no-restricted-imports` and `allowTypeImports: true`: on `src/main.ts`, `src/bootstrap.ts`, `src/infrastructure/**/*.ts` against `presentation/<module>(/index)?`; on `src/presentation/*.ts` against `./<module>(/index)?`; on `src/presentation/*/screens.ts` against `vue`, `@vue/*`, `@nuxt/*`, `@tanstack/*`, `*.vue`, `./index` and `../<module>(/index)?` (global constraint 5).
  - For each core module, blocks over its folders that refuse every module listed after it (`Module shell never imports notes: feature → notes → shell`).
  Adding a module never edits this file.
- [ ] **6. The fallow source** (`configs/fallow.config.mjs`, exports `fallowConfig({ modules, has })`). fallow reads only JSON and knows no placeholder for "every module" (L15), so this JS file is the source and `configs/fallow.json` is generated. Contents:
  - `$schema`, `entry` (empty until Task 11 adds `harness/main.ts`), `supportEntry` for `scripts/*.mjs`, `tests/**/*.test.ts`, `tests/e2e/**/*.ts`, `tests/e2e/wdio.conf.mts`, `configs/*.ts`, `configs/*.mjs`, `*.config.mjs`; `ignorePatterns` as oxlint's; `duplicates: { minTokens: 50 }`; `health: { maxCyclomatic: 10 }`. fallow takes `src/main.ts` as an entry by itself (seen in the source with `npx fallow dead-code -c configs/fallow.json --trace src/main.ts:default`), and a file that a test imports counts as used.
  - `boundaries.zones`: `domain`, `application`, `adapters` (`src/infrastructure/obsidian`), `memory`, `presentation` each with `autoDiscover` and `publicFiles: ["index.ts"]` (presentation also `screens.ts`); before the discovered ones the hand-declared zones `presentation/shell` (public `index.ts`, `host.ts`, `screens.ts`) and, from Task 13, `application/notes-adapter`; the composition zones `application-module` (`src/application/module.ts`), `application-describe-error` (`src/application/user-messages.ts`, because `presentation/shell` calls it at runtime while it may import the other root files only as types), `application-composition` (`src/application/**`), `infrastructure` (`src/infrastructure/**`), `presentation-composition` (`src/presentation/**`), `composition` (`src/main.ts`, `src/bootstrap.ts`).
  - `boundaries.rules`: the layer rules, where a discovered zone may import a sibling zone only if the rule names it and a rule cannot name its own group as a whole, so each layer rule lists `<layer>/<module>` for every module that has a folder in that layer (`siblings(folders, zone, folder)`; fallow refuses a rule naming a zone with no folder); explicit rules for the `shell` zones (only `domain/shell`, `application-module`, types of `application-composition`) and later the `notes` zones; `coverage.requireAllFiles: true` with `allowUnmatched` for `src/env.d.ts`, `src/styles/**`, `tests/**`, `scripts/**`, `harness/**`, `configs/**`, `*.mjs`.
  - `ignoreDependencies` for packages used only by a CLI or a config fallow cannot see (in the source: `obsidian`, `@iconify-json/lucide`, `@eslint/js`, `wdio-obsidian-reporter`, `@wdio/local-runner`, `@wdio/mocha-framework`); add each with the task that installs it. `overrides: [{ files: ["tests/support/obsidian/**"], rules: { "unused-class-members": "off" } }]` (the double mirrors Obsidian's API, Task 04).
- [ ] **7. The generator** (`scripts/fallow-config.mjs`). Tests first (`tests/unit/scripts/fallow-config.test.ts`): the same module list and folders give the same text; a module without a folder in a layer is left out of that layer's rule; `--check` returns the message `configs/fallow.json does not match the module list: run \`npm run fallow:config\`.` for a stale file and nothing for a current one. Then `fallowJson({ modules, has })` formats `JSON.stringify(fallowConfig(…))` with Prettier's options for the target file, and `syncFallowJson({ check })` writes or compares. Scripts: `fallow:config`: `node scripts/fallow-config.mjs`; `analyze`: `node scripts/fallow-config.mjs --check && fallow -c configs/fallow.json && fallow architecture -c configs/fallow.json` (always `-c`: fallow did not discover a config named `fallow.json` by itself). Run `npm run fallow:config` and commit the generated file. Add `analyze` to `STEPS` after `test:coverage`.
- [ ] **8. The list test** (`tests/unit/application/modules.test.ts`): every folder in `src/{domain,application,infrastructure/obsidian,infrastructure/memory,presentation}` is a name in `APP_MODULES`; every listed module has `src/application/<name>/module.ts` and (from Task 10) `src/presentation/<name>/screens.ts`; `readModules().all` equals the manifests' names, each once; no error tag and no section id belongs to two modules; `keyof Catalog` equals `AppModuleName` (`expectTypeOf`, once `messages.ts` exists in Task 05).
