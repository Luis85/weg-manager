# Task 08 · Build, CSS ownership, dist invariants

Phase A. Needs: Task 07.

**Goal.** `npm run build` writes exactly the three files Obsidian loads; every style the plugin ships stays inside its own root and derives its colours from the host; nothing is fetched at runtime; a script checks all of it on every gate run.

## Files

Create: `configs/vite.shared.ts`, `configs/vite.config.ts`, `scripts/scope-css.mjs`, `scripts/no-head-plugins.mjs`, `scripts/check-dist.mjs`, `scripts/dev-install.mjs`, `src/styles/{app,tokens,bridge}.css`, `tests/unit/scripts/{scope-css,check-dist,no-head-plugins}.test.ts`. Modify: `src/main.ts` (`import "./styles/app.css";`), `configs/vitest.config.ts` (the dom project gets `sharedConfig({ mode: "test" })`'s plugins and `define`), `package.json` (scripts `build`, `check:dist`, `dev`), `scripts/verify.mjs` (add `build`, `check:dist`).

Install: `@nuxt/ui`, `tailwindcss` (`dependencies`); `vite`, `@vitejs/plugin-vue`, `postcss`, `postcss-selector-parser`, `@iconify-json/lucide` (`devDependencies`; add `@iconify-json/lucide` to fallow's `ignoreDependencies`). `vue` is installed here too (a `dependencies` entry: it is a peer of `@vitejs/plugin-vue` and `@nuxt/ui`, and the build needs it); until Task 09 first imports it, list it in fallow's `ignoreDependencies` and remove the entry then (Untested proposal, like the install order of Task 01). `@iconify/vue` follows in Task 09. If `npm run analyze` reports a package unused, install it with the task that imports it, or list it in `ignoreDependencies` when only a CLI or config uses it.

## Steps

- [ ] **1. `scopeCss({ id, prefix, skip? })`** (`scripts/scope-css.mjs`, a PostCSS plugin; `SCOPE_CLASS = "<plugin-id>-root"`). Tests first, input → output after normalising whitespace:
  - `.a{}` → `.<plugin-id>-root .a{}`; `:root{--x:1}` and `:host{--x:1}` → `.<plugin-id>-root{--x:1}`; `.dark{…}`/`.light{…}` → `.<plugin-id>-root.dark{…}` (the theme class sits on the root);
  - `html{…}` → `.<plugin-id>-root{…}`; `body .a{…}` → `.<plugin-id>-root .a{…}`; `html body{…}` → `.<plugin-id>-root{…}`; `*{…}` → `.<plugin-id>-root *{…}` (so `html` and `body` at the start of a selector stand for the root and are never emitted bare, and `*` is prefixed like any selector); a selector already starting with the scope is not scoped twice;
  - `@layer base{.a{}}` → `.<plugin-id>-root .a{}` with no `@layer` left (Obsidian's unlayered rules would otherwise win), and empty `@layer a, b;` statements removed;
  - `@keyframes spin` → `@keyframes <css-prefix>-spin` with `animation`/`animation-name` rewritten, an already prefixed name left alone; `@property --tw-x` → `@property --<css-prefix>-tw-x` with every use renamed;
  - selectors inside `@media`, `@supports`, `@container` are scoped, keyframe steps are not; the line break before a selector is ignored; files matched by `skip` (the harness's fake host, Task 11) stay as written.
- [ ] **2. `noHeadPlugins()`** (`scripts/no-head-plugins.mjs`, a Vite `resolveId`/`load` plugin). Nuxt UI's `runtime/plugins/colors.js` appends `<style id="nuxt-ui-colors">` to `document.head` on the first mount, and `runtime/vue/plugins/head.js` exists only to serve it (L19). Resolve both to no-op modules, **one module each** (Vue warns when one plugin object is installed twice), and pin each replaced file by sha256 in `REPLACED`, so a Nuxt UI upgrade that changes one fails the build until it is reviewed again (`checkPins`). Test: `tests/unit/scripts/no-head-plugins.test.ts`.
- [ ] **3. `configs/vite.shared.ts`**, `sharedConfig({ mode, skipScope? })`, used by the build, the harness and the dom tests: `PLUGIN_ID`, `CSS_PREFIX`, `SHELL_ICONS`; plugins `noHeadPlugins()`, `vue()`, `ui({ router: false, colorMode: false, autoImport: false, components: false, theme: { prefix: CSS_PREFIX }, icon: { mode: "svg", clientBundle: { icons: SHELL_ICONS } } })` from `@nuxt/ui/vite`; PostCSS `scopeCss`; `define` for `process.env.NODE_ENV`, `import.meta.dev: "false"`, `__VUE_OPTIONS_API__: "true"` (third-party components may use it), `__VUE_PROD_DEVTOOLS__: "false"`, `__VUE_PROD_HYDRATION_MISMATCH_DETAILS__: "false"`. `SHELL_ICONS` lists every `lucide:*` icon the plugin uses beyond Nuxt UI's own defaults; a new icon is a line here (L18).
- [ ] **4. `configs/vite.config.ts`**: `root` = repository root; `lib` entry `src/main.ts`, format `cjs`, file `main.js`, `cssFileName: "styles"`, `cssCodeSplit: false`; `rolldownOptions.external` = the host externals of global constraint 7; `output: { exports: "default", codeSplitting: false }` (Vite 8 / rolldown names); target `es2022`; minified unless `--mode development`, then an inline sourcemap; a small plugin that emits the root `manifest.json` as `dist/manifest.json`. Task 20 adds `bundledPackages`. Script `build`: `vite build --config configs/vite.config.ts`.
- [ ] **5. Styles.**
  - `src/styles/app.css`: `@layer theme, base, components, utilities;` then `@import "tailwindcss/theme.css" layer(theme) prefix(<css-prefix>);`, `@import "tailwindcss/utilities.css" layer(utilities) source(none);` (**no preflight**, no automatic content detection), `@source "../presentation";`, `@import "@nuxt/ui";`, then `@source not` for `../../node_modules/.nuxt-ui/ui` and `../../node_modules/@nuxt/ui/dist/runtime/components`, and `@source` lists of exactly the component themes (`.nuxt-ui/ui/{app,button,…}.ts`) and `.vue` files (`@nuxt/ui/dist/runtime/components/{App,Button,…}.vue`) the plugin renders, including those they render inside (L20: scanning everything exceeds the 250 KB budget). Clear the unused palettes (`--color-old-neutral-*: initial; --color-neutral-*: initial;` in `@theme`). Then `tokens.css` and `bridge.css`.
  - `src/styles/tokens.css`: plugin tokens (`--<css-prefix>-bg`, `-bg-secondary`, `-border`, `-line-strong`, `-text`, `-text-muted`, `-accent`, `-on-fill`, `-primary-fg`, `-primary-fill`, `-warn-fg`, `-warn-fill`, `-bad-fg`, `-bad-fill`, `-ok-fg`, `-ok-fill`, `-font`, `-font-mono`, `-radius`) mapped once from Obsidian variables (`--background-primary`, `--background-secondary`, `--background-modifier-border`, `--text-normal`, `--text-muted`, `--interactive-accent`, `--text-on-accent`, `--text-error`, `--text-warning`, `--text-success`, `--font-interface`, `--font-monospace`, `--radius-s`), and **derived** colours, never a host hue raw for text or a fill (L25): text shades `color-mix(in oklab, <hue> 55%, var(--text-normal))` for primary (accent), warning, error, success; fill shades under on-accent text `color-mix(in oklab, <hue> 60%, black)`; a field boundary `color-mix(in oklab, var(--text-muted) 70%, var(--background-primary))`; the raw accent only for focus outlines (3:1). One formula per token, light and dark alike, so community themes get the same treatment.
  - `src/styles/bridge.css`: Nuxt UI's `--ui-*` roles set from the tokens for `:root`, `.light`, `.dark` (Nuxt UI's own theme blocks use those classes and would otherwise win by specificity). Every role, with its token (prefix `--<css-prefix>-` left out): `--ui-bg` `bg`; `--ui-bg-muted` and `--ui-bg-elevated` `bg-secondary`; `--ui-bg-accented` `border`; `--ui-bg-inverted` `text`; `--ui-text`, `--ui-text-toned` and `--ui-text-highlighted` `text`; `--ui-text-dimmed` and `--ui-text-muted` `text-muted`; `--ui-text-inverted` `on-fill`; `--ui-border` and `--ui-border-muted` `border`; `--ui-border-accented` `line-strong` (form fields and outline buttons draw their 3:1 boundary with it); `--ui-border-inverted` `text`; `--ui-primary`, `--ui-secondary` and `--ui-info` `primary-fg`; `--ui-error` `bad-fg`; `--ui-success` `ok-fg`; `--ui-warning` `warn-fg`; `--ui-radius` `radius`; `--ui-chart-1` `accent`, `--ui-chart-2` to `-6` Obsidian's `--color-blue`, `--color-purple`, `--color-orange`, `--color-red`, `--color-cyan`; plus `font-family` and `color` from `font` and `text`. Nuxt UI's runtime colors plugin is replaced (step 2), so no role may be left unset; on solid fills (`.<css-prefix>\:text-inverted`, which Nuxt UI's solid button, alert and badge put on `bg-<role>`) the six colour roles switch to the fill shades (`primary-fill` for primary, secondary and info, `bad-fill`, `ok-fill`, `warn-fill`); a portal class with `position: relative; z-index: var(--layer-modal, 50)` (a later view must not paint over an earlier view's modal backdrop); the owned reset instead of preflight (`box-sizing`, zero borders, form font inheritance, focus-visible outline, a `forced-colors` block); and a **base reset below the utilities**: inside the root, `ol`/`ul`, headings, `p`, `fieldset`, `legend` start from zero and `button:not(svg)` drops Obsidian's chrome. Scoped, these weigh (0,1,1) and (0,1,2): above Obsidian's element rules, below every utility (0,2,0). Do not raise them. Text inputs are not reset (Obsidian's `input[type=text]:hover` weighs (0,2,1)).
  A git worktree needs a real `node_modules` there, or at least real copies of `@nuxt/ui` and `.nuxt-ui`: a symlinked `node_modules` breaks the `@source not` excludes and `styles.css` changes (L37).
- [ ] **6. `checkDist(dir, rootManifest, { id, prefix })`** (`scripts/check-dist.mjs`, also a CLI; `EXPECTED_FILES`, `BUDGETS`, `CSS_PREFIX`). Tests first on temp-dir fixtures (`tests/unit/scripts/check-dist.test.ts`): passes a valid fixture and reports each of a missing file, an extra file, `manifest.json` differing from the root one, no `module.exports =`, a `require("…")` of anything but a host external or Node builtin, a string-literal `fetch(`/`.open(` target starting with `http`, the test-only marker `<plugin-id>/test-only` (add this case and its rule in Task 13 step 10, with the first adapter that carries it), an unscoped selector, a surviving `@layer`, an unprefixed `@keyframes` or `@property`, `main.js` over 1.5 MB, `styles.css` over 250 KB. Script `check:dist`: `node scripts/check-dist.mjs`.

Script `dev`.
- [ ] **8. One identity, several copies.** `<plugin-id>` and `<css-prefix>` appear as constants in `configs/vite.shared.ts` (`PLUGIN_ID`, `CSS_PREFIX`), `scripts/scope-css.mjs` (`SCOPE_CLASS`), `scripts/check-dist.mjs` (`CSS_PREFIX`), `src/presentation/shell/scope.ts` (`SCOPE_CLASS`, `PORTAL_CLASS`, Task 09), `scripts/no-head-plugins.mjs` (its module prefix), the service keys, the console sink prefix and `tests/e2e/support.ts`. Pin each pair by a test: `SCOPE_CLASS` of `scope.ts` against the script's in `tests/dom/presentation/shell/mount.test.ts` (Task 09), the test-only marker in `tests/unit/scripts/check-dist.test.ts` (Task 13), and `CSS_PREFIX` of `check-dist.mjs` against `vite.shared.ts`'s in `tests/unit/scripts/check-dist.test.ts` now.

## Done when

`npm run build` writes three files; `npm run check:dist` exits 0; `npm run verify` exits 0 with `build` and `check:dist` in its summary. Discriminating checks: remove `noHeadPlugins()` from `sharedConfig`; Task 09's head test fails (come back to this check after Task 09). Change one byte of a pinned Nuxt UI file in `node_modules`; the build fails naming it; reinstall. Commit `build: plugin bundle, CSS ownership and dist invariants`.

What no test of this task checks: the specificity of the base reset and the colour tokens show only in a real Obsidian window. `appearance.e2e.ts` (Task 18) measures them in Obsidian's default theme, light and dark: lists, headings and paragraphs start from zero, ghost buttons carry no Obsidian chrome, every visible text reaches 4.5:1 and field boundaries 3:1. Until then, check them by eye in the harness (Task 11). Reported size of a first feature on this stack (not reproducible from this folder): `styles.css` about 72 KB, far below the budget.
