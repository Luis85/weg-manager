# Task 13 · The note store

Phase B (skip for a plugin without note data). Needs: Task 12.

**Goal.** Every feature reaches the vault through one port in domain terms, `NoteStore`. Its Obsidian adapter is the only code that changes vault files; an in-memory adapter serves the tests and the harness; one contract suite runs against both; fidelity scenarios run the same steps on the double and in real Obsidian and compare them with one expectation (L31). This task builds reads, create, rename, trash and the opener; Task 14 builds `update`.

## Steps

- [ ] **1. The root folder setting** (`src/domain/shell/root-folder.ts`, a second `FIELDS` entry): `rootFolder`, default `<root-folder>`, `omitWhenDefault: true`, issue `rootFolder.invalid` with `max: ROOT_FOLDER_MAX_LENGTH` (100). Stored normalised: trimmed, no leading or trailing slash, `/` between names; no empty name; no name that starts with a dot (Obsidian does not index hidden folders, so notes there would never be listed; this also covers `.`, `..` and the config folder); none of `* " \ < > : | ?` and no control character. It has no UI (one edit location: a power user edits `data.json`). Test: `settings-root-folder.test.ts`.
- [ ] **2. The port** (`src/application/notes/ports.ts`), plain data, never `TFile`. A note is `{ path, frontmatter }`:
  | Call | Does |
  | --- | --- |
  | `list` | every record: a Markdown note whose frontmatter `schema` starts with `<plugin-id>.`, anywhere in the vault, sorted by path, from the metadata cache, no file contents |
  | `read(path)` | one note; `{}` for no frontmatter or broken YAML |
  | `unreadable(folder)` | the paths of Markdown notes in `folder` or below whose frontmatter block cannot be read, sorted |
  | `create({ folder, name, frontmatter, body? })` | missing folders and the note in one `vault.create`; a taken name gets ` (2)`, ` (3)`, … up to `MAX_NAME_ATTEMPTS` (100) |
  | `update(path, change)` | Task 14 |
  | `trash(path)` | `fileManager.trashFile`, so the user's *Deleted files* setting applies; a failed move is `NoteTrashError` |
  | `rename(path, newName)` | `fileManager.renameFile` in the same folder, so Obsidian updates links; another note's name is `NotePathTakenError`; the note's own name in another case is allowed |
  Beside it: `NoteOpener.open(path)` (use case `openNote`: `workspace.getLeaf("tab").openFile(file, { active: true })`, so the plugin's fixed tab stays; no Markdown note there is `NoteNotFoundError`) and `IdGenerator` (`crypto.randomUUID()` in the plugin, `sequentialIdGenerator()` in tests and the harness).
- [ ] **3. Errors** (`src/application/notes/errors.ts`, each in `NOTES_ERROR_TAG_KEYS` of the manifest): `NoteNotFoundError` (also for a note deleted between lookup and write), `NotePathTakenError`, `InvalidNoteNameError` (issues `empty`, `forbidden-character`, `leading-dot`), `NoteUnreadableError`, `NoteWriteError` (the vault call failed; never for a throw of the plugin's own code, which `asDefect` turns into a defect), `NoteTrashError` (the user reads "not deleted", not "not saved"); reads fail with the shell's `VaultReadError`. None carries a path. Texts in the notes catalog.
- [ ] **4. Writes are commands** (`writeCommand`, `src/application/notes/command.ts`): the vault calls run in `Effect.uninterruptible`, so once started they complete even when the caller is interrupted (L4); checks that write nothing (name, free path, note exists) run before it. Test: `command.test.ts`.
- [ ] **5. Name clashes** (`clashKey(name) = name.normalize("NFC").toLowerCase()`, `src/domain/notes/notes.ts`). Two names clash when their keys are equal: NFC first because macOS writes umlauts decomposed; `toLowerCase`, not `toLocaleLowerCase` or `localeCompare`, because it is Unicode's default case mapping, the same in every locale and engine. The store compares a candidate with every file **and folder** in the target folder (`TFolder.children`), because Obsidian's lookups by path are case-sensitive and a Linux disk would take both names; Windows and macOS would not. `noteNameIssue(name)` gives the name issues of step 3.
- [ ] **6. The adapter kit** (`src/application/notes/adapter.ts`, the second entry, imported only by `src/infrastructure/**`): `writeCommand`, `createNote`, `asDefect`, `copyFrontmatter`, `recordNotes`, `pathsInFolder`, `planRename`, and from Task 14 `newNoteText`, `updateNoteText`. The kit imports the rest of the module through its `index.ts`; the module's other files never import the kit. ESLint: `kitOutside` refuses `notes/adapter` everywhere but `src/infrastructure/**`, `kitElsewhere` refuses any other layer's `notes/adapter` there. fallow: the zone `application/notes-adapter` (`adapter.ts`, `command.ts`, `frontmatter.ts`, `note-text.ts`, `paths.ts`) with `adapter.ts` its only public file, importable only by `adapters`, `adapters/notes` and `memory`.
- [ ] **7. The Obsidian adapter** (`src/infrastructure/obsidian/notes/note-store.ts`): `vault.create`, `vault.createFolder`, `vault.process` (Task 14), `fileManager.trashFile`, `fileManager.renameFile`, every path through `normalizePath`; no `vault.modify`, no `vault.adapter`, no `read` followed by a write, no `fileManager.processFrontMatter` (L6). **The cache lags** a write by a few milliseconds: right after `create`, `getFileCache` is `null`; right after an update it holds the old frontmatter. So every write returns the note as written, and `list`/`read` show what the cache holds (L9). **Unreadable frontmatter** (measured in Obsidian 1.15.1): broken YAML or YAML that is no map leaves the cache without `frontmatter` and `frontmatterPosition`, like a note without a block; only `sections` tells them apart (a `yaml` section from line 0 to the closing fence). Report a note with a `yaml` section but no `frontmatter`, unless the section is just two fences.
- [ ] **8. The in-memory adapter** (`memoryNoteStore()`, `src/infrastructure/memory/notes/`): notes as data, not text (byte fidelity is the Obsidian adapter's). Handles: `seed(path, frontmatter | "none" | "broken", body)`, `removeOutside(path)`, `body`, `isFolder`, `setFailReads`, `setFailWrites`, `holdWrites`/`releaseWrites`/`heldWrites`, and `opener` (records `opened()`). Reads see writes at once. Built where an `EventBus` is, it publishes the same file events for its writes and seeds that `hostEventsLayer` publishes for the Obsidian adapter, step by step as `tests/support/notes/store-events.ts` lists them; both sides are checked against that list (`memory-note-store-events.test.ts`, `tests/dom/infrastructure/notes/store-events.test.ts`). Every made-up failure carries `TEST_ONLY_MARKER = "<plugin-id>/test-only"`; `check:dist` rejects a `main.js` that holds it (a planted import of the in-memory store into `appLayer` must fail `check:dist`, ESLint and fallow). Nothing in `src/` imports `memory/`.
- [ ] **9. The double's vault** (as Obsidian 1.15.1 behaves): `vault` with `getFileByPath`, `getFolderByPath`, `getAbstractFileByPath`, `getMarkdownFiles`, `getRoot()`, `read`/`cachedRead` (without a leading BOM, as Obsidian decodes), `create` (refuses a taken path and a missing folder), `createFolder` (parents too, one `create` each), `process` (Task 14); each write waits a macrotask first and refuses a path `normalizePath` would change; `TFile` and `TFolder` are classes (`instanceof` works), `TFolder.children` kept current. `metadataCache.getFileCache` indexes a write a macrotask later, then fires `changed`, `resolve`, `resolved`; `null` before a new file is indexed; broken YAML has no `frontmatter`; the block is a `sections` entry of type `yaml`; `whenIndexed()` waits for pending files. `fileManager.renameFile` (keeps the `TFile`, fires `rename`), `trashFile` (`metadataCache` `deleted`, `vault` `delete`, then `resolved`; resolves `true`), `processFrontMatter` (kept only so the fidelity scenarios can record it). `parseYaml`, `stringifyYaml`, `YAMLParseError` for flat maps of text, numbers, booleans, null and lists, LF or CRLF; it rejects what records never hold instead of guessing. Knobs: `failReads`, `failWrites`, `holdWrites()`/`releaseWrites()`/`heldWrites()`, `seedFile(path, text)` (from outside: Sync, another app; also a path in NFD), and `caseInsensitive = true` (Windows and macOS: a write onto a path that differs from another only in case or Unicode form fails with EEXIST; lookups stay exact, as Obsidian's are). Not modelled: link updates on rename, folder renames, `vault.modify`, `vault.delete`.
- [ ] **10. The contract** (`tests/support/notes/contract.ts` with `contract-reads.ts`, `contract-writes.ts`, `contract-clashes.ts`; `contract-opener.ts`): the same cases against the in-memory adapter (`memory-note-store.test.ts`) and the Obsidian adapter on the double, once on a case-sensitive and once on a case-insensitive disk (`obsidian-note-store.test.ts`). A behaviour the port promises goes into the contract, not into one adapter's test: records recognised by `schema` anywhere, unknown keys and key order kept, clash suffixes in case and NFC/NFD, rename onto another note, rename to its own name in another case, a note deleted while a write waits fails `NoteNotFoundError`, a throw of `change` is a defect and writes nothing (Task 14).
- [ ] **11. Fidelity scenarios** (`tests/support/notes/scenarios.ts`, expectations in `fidelity.ts`): `vaultFacts` calls the vault, metadata cache and file manager directly (`normalizePath`, YAML, create, createFolder, process, processFrontMatter, renameFile, trashFile, their errors and events, the cache's lag); `storeScenario` drives the `NoteStore` through the probe API (`probe-api.ts`); `readinessScenario` (`tests/support/readiness-scenario.ts`) records `changed`, `resolve`, `resolved`, `deleted` around a create, an edit and a trash. `tests/unit/support/obsidian-double.test.ts` runs them on the double, `note-store.e2e.ts` in Obsidian; both compare with the same expectation. A difference is a bug in the double: fix the double, never the expectation alone. Keep each step to what Obsidian does the same every run (whether a new file's index or an immediate write to it comes first varies, so steps settle in between). `executeObsidian` sorts the keys of what it returns and turns `undefined` into `null`, so the scenarios return plain JSON and show key order through file texts.
- [ ] **12. The probe plugin** (`tests/e2e/probe-plugin/`, built by `npm run build:probe` with `configs/vite.probe.config.ts` from the real adapter source into `tests/e2e/probe-plugin/dist/`, git-ignored, installed beside `dist/` by `wdio.conf.mts`): exposes the Obsidian `NoteStore` as `plugins.noteStoreProbe.api`, so a spec calls the store without any hook in the plugin itself. Task 16 adds its `events` and `startup` recorders.
