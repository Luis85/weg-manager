# Task 02 · Toolchain and the gate

Phase A. Needs: Tasks 00 and 01.

**Goal.** Type checking, two linters, a formatter and the test runner, each enforcing its part of the global constraints, run by one gate script from now on. Every rule is proven with a planted violation before it counts.

Install (versions from ADR 0001, all `devDependencies`): `typescript`, `vue-tsc`, `@types/node`, `oxlint`, `eslint`, `@eslint/js`, `typescript-eslint`, `eslint-plugin-vue`, `vue-eslint-parser`, `eslint-plugin-obsidianmd`, `eslint-plugin-oxlint`, `globals`, `prettier`, `vitest`, `@vitest/coverage-v8`, and `obsidian` (the API types: `tests/unit/obsidian-guard.test.ts` imports `obsidian`, which typecheck cannot resolve without the package; Task 03 lists it in fallow's `ignoreDependencies`).

## Where configs live

Tool configs go into `configs/` only where the tool takes an explicit path and keeps resolving from the repository root. These stay at the root: `.oxlintrc.json` (oxlint resolves `ignorePatterns` and `overrides` relative to its file; moved into `configs/`, the layer bans silently stopped applying, L17), `eslint.config.mjs` (flat-config patterns resolve from its folder), `tsconfig.json` (editors), `.prettierrc.json` and `.prettierignore` (editors search upward), and the dotfiles of Task 00.

- [ ] **7. The gate** (`scripts/verify.mjs`). The gate is a list of stages: the steps of one stage start together, the next stage starts when all of them have ended. Tests first in `tests/unit/scripts/verify.test.ts`, with an injected fake spawn whose steps end when the test says so: the checks of the first stage start together and the next stage waits for the slowest; a step that shares a stage is buffered and printed whole when it ends, framed by `--- <name> ---` and `--- <name>: ok, 12.3 s ---` (or `FAIL (exit <code>)`), so lines of two steps never mix; when a step of a stage fails, the others of that stage still finish and print, and then no later stage starts; the exit code is that of the first failed step in stage order, else 0; `summary` marks `ok`, `FAIL` and `not run` with seconds and ends with the wall-clock total. Add two tests that start real `node` processes for the buffering. Then implement:
  - `PARALLEL = ["format:check", "lint", "typecheck"]` (they read the sources and write nothing, so they do not disturb each other; lint sets the pace) and `SERIAL`, the later npm scripts, each a stage of its own and in this order; the final list is `test:coverage`, `analyze`, `build`, `check:dist`, `check:notices` (the last two read the fresh `dist/`). Add each when its script exists: now `test:coverage`, `analyze` in Task 03, `build` and `check:dist` in Task 08, in Task 20 `check:notices` and, as a fourth check of `PARALLEL` (it reads three JSON files and writes nothing), `check:versions`. `STAGES = [PARALLEL, ...SERIAL.map((step) => [step])]`. The test pins the current list.
  - `FULL_STAGES = [...STAGES, [test:mutation]]` (Task 19 adds the script); `FORMAT_STAGES = [[format:check]]` for the hook (step 8).
  - `spawnStep(step, buffer)`: a step alone keeps the terminal (`stdio: "inherit"`), a buffered one pipes stdout and stderr (with `FORCE_COLOR=1` when the terminal has colours and `NO_COLOR` is unset); `shell: process.platform === "win32"` (npm is a `.cmd` shim on Windows); a spawn error counts as code 1.
  - `runStages(stages, spawn, print)`, `summary(results, steps, totalMs)`, `exitCode(results)` and `runGate(stages, io)`, which runs, prints the summary and returns the code. CLI: `--full` picks `FULL_STAGES`; `process.exitCode` is `runGate`'s result.
  - **The CLI guard** (`scripts/is-cli.mjs`, test first in `tests/unit/scripts/is-cli.test.ts`). `isCli(import.meta.url, argv1 = process.argv[1])` says whether a script was started as the program: it compares `realpathSync` of both and is false for no argument or a path that does not exist. Every script of this plan that runs on its own ends with `if (isCli(import.meta.url)) { … }` (this one, `pre-push.mjs`, `install-hooks.mjs` and the scripts of Tasks 03, 08, 16 and 20). A plain `resolve(process.argv[1]) === fileURLToPath(import.meta.url)` is false when the script is started through a symlink (a linked checkout, a package manager's bin link): the script then does nothing and exits 0, which a gate reads as success (L44). `import.meta.main` would do, but needs Node 24.2 and `engines` says `>=24`. The test covers the own path, a symlink, another file, no argument and a missing path, starts one real script through a symlink and expects its usage line, and reads every script and fails on a comparison with `process.argv[1]`.
  Scripts `verify`: `node scripts/verify.mjs`; `verify:full`: `node scripts/verify.mjs --full`. Do not add ESLint's `--cache` to `lint`: its cache keys on a file's own content and the config, while a type-aware finding can depend on another file. Planted and measured: `a.ts` switches over every member of a union from `b.ts`; after only `b.ts` gains a member, `eslint --cache` still exits 0 (with `--cache-strategy metadata` and `content`) and the same run without the cache fails `switch-exhaustiveness-check`. If lint gets slow, use fewer type-aware rules or a smaller project, not a cache.

Tests first in `tests/unit/scripts/pre-push.test.ts`:
