# Task 09 · Surface and runtime bridge

Phase A. Needs: Task 08.

**Goal.** A view's Vue app mounts lazily, lives entirely in its view's document, and reaches the application only through a small bridge whose reads may be cancelled and whose writes never are. Plugin load evaluates no Vue.

## Files

Create in `src/presentation/shell/`: `host.ts` (Vue-free entry), `index.ts` (Vue entry), `surface.ts` (`loadSurface`), `mount.ts`, `release.ts` (`releaseAll`), `scope.ts` (`SCOPE_CLASS`, `PORTAL_CLASS`), `theme.ts` (`bindHostTheme`), `icons-offline.ts` (`keepIconsOffline`), `modal.ts` (`useModal`), `delay.ts` (`useDelayed`), `runtime/use-runtime.ts`, `runtime/use-stream.ts`, `components/{ShellApp,ErrorNotice,NotFoundState}.vue`. Tests: `tests/dom/presentation/shell/{mount,theme,use-runtime,use-command,use-stream,error-notice,icons-offline}.test.ts`, `tests/dom/lazy-presentation.test.ts`, `tests/unit/presentation/shell/{host,release}.test.ts`, `tests/support/{wait,preload,composable}.ts`.

Install: `vue`, `@iconify/vue`, `@vue/test-utils`.

## Steps

- [ ] **1. Two entries** (L3, ADR 0006 amendment in the source). `index.ts` serves feature components and may load Vue: the composables, `ErrorNotice`, `NotFoundState`, `mountSurface`, and later `SettingsScreen`, `useRoute`, `useNavigate`, `useHistory`. `host.ts` serves plugin-load code (`bootstrap`, the Obsidian adapters, `src/presentation/*.ts`) and must not evaluate Vue: `releaseAll`, `loadSurface`, `memoryNavigation` (Task 10) and the surface types. `loadSurface = () => import("./mount")`: rolldown turns the dynamic import into a lazy init inside the one `main.js` (`codeSplitting: false`). Tests: `tests/unit/presentation/shell/host.test.ts` fails if importing `host.ts` evaluates Vue; `tests/dom/lazy-presentation.test.ts` loads the plugin through `main.ts` and finds Vue, Nuxt UI and TanStack Form unevaluated until a view opens. That file must not call `preloadSurface()`.
- [ ] **2. `releaseAll(releases)`**: runs every release in reverse order even if one throws, then rethrows the first error. Test: `tests/unit/presentation/shell/release.test.ts`.
- [ ] **3. `mountSurface(root, runtime, { surface, navigation, content? })`**: adds `SCOPE_CLASS` to `root`; `bindHostTheme(root)`; creates the app element and a portal element (`PORTAL_CLASS`) with `root.ownerDocument`, attaches both to `root` **before** mounting (floating UI and focus handling measure a connected element); `app.config.idPrefix` random per mount (no module-level counter); `app.config.errorHandler` → `reportVueError` → `reportDefect` once; `provideRuntime`; `keepIconsOffline()`; `app.use(ui)` from `@nuxt/ui/vue-plugin`; mounts `ShellApp`. Returns an idempotent close through `releaseAll` that leaves `root` without children and without added classes. `ShellApp.vue` wraps the content in `UApp` with `:portal` set to the portal element and `:toaster="null"` (notifications go through `Notifier`), sets Nuxt UI's locale (`@nuxt/ui/locale`) from the shell catalog's `language` entry, and provides the modal registry. Import every Nuxt UI component explicitly from `@nuxt/ui/components/<Name>.vue`, never auto-registered, and add each to `app.css`'s `@source` lists. Tests (`mount.test.ts`):
  - `document.head.childElementCount` is the same before mounting, after mounting and after opening a modal (CSS ownership; the discriminating check of Task 08);
  - mounted into a root of `document.implementation.createHTMLDocument()`, an opened modal's content is a descendant of that root and the main `document.body` gained nothing (pop-out);
  - two roots on one runtime, the first closed: the second still updates;
  - a child that throws in render: one defect notice, the rest of the surface rendered;
  - closing twice is a no-op; `SCOPE_CLASS` equals `scripts/scope-css.mjs`'s.
- [ ] **4. `bindHostTheme(root)`**: mirrors `theme-dark`/`theme-light` on `root.ownerDocument.body` to `dark`/`light` on `root` with the `MutationObserver` of `root.ownerDocument.defaultView`; the release disconnects and restores the original classes. No `css-change` host event (L21). Test: `theme.test.ts`.
- [ ] **5. `keepIconsOffline()`**: `_api.setFetch(noIconsOnline)` from `@iconify/vue`, where `noIconsOnline` answers `new Response(null, { status: 404 })`; the Iconify client then abandons the query, and a missing icon is an empty space instead of a request to `api.iconify.design` (L18). The API resources cannot be emptied instead: `addAPIProvider` rejects an empty list. Test: `icons-offline.test.ts` sees no request after Iconify's batch timer (the one place where waiting a fixed time is right: it proves that nothing happens).
- [ ] **6. The runtime bridge** (`runtime/`, the only presentation folder that imports `effect`). `provideRuntime(app, runtime)`/`useRuntime()` through provide/inject; `useMessages()` (the `Catalog` of this load, a plain value). Tests first (`use-runtime.test.ts`, `use-command.test.ts`, `use-stream.test.ts`), with `testRuntime().source` from Task 06 and `tests/support/composable.ts` (mounts a composable in a throwaway component):
  - `useQuery(fn)` for reads: `run`, `pending`, `value`, `error`, `message` (`describeError` in the UI language). The latest call wins: a second `run` interrupts the first; the scope ending interrupts a pending run and drops its result.
  - `useCommand(fn)` for state changes (L4): **nothing in the component interrupts it**, neither a second `run` nor the scope ending; only disposing the runtime does. A `run` while one is pending starts nothing and returns the pending run's promise. After the scope ended the run still completes; a success is silent, a typed failure becomes a notice, a defect is reported once.
  - Both: `run` resolves to a `RunOutcome`: `{ _tag: "success", value }`, `{ _tag: "failure", error, message }`, `{ _tag: "defect" }` (already reported) or `{ _tag: "interrupted" }`. A run clears `value`, `error` and `message` when it starts. Code that goes on after `await run(…)` decides on the outcome, never on the refs (a defect leaves `error` empty too). Each run's `Exit` goes through `reportUnexpected`.
  - `useStream(read, changes)`: `read` must not suspend and gives the value from the first render; `changes` gives every later value until the scope ends; a defect in `changes` is reported once and the ref keeps its last value. `useSettings()` and `useSettingsStatus()` are `useStream` over `SettingsService`.
  - `useAppEvents` (a component subscribes to the bus) is kept in the source without a user in `src/`; build it with its first consumer (L21).
- [ ] **7. Shared components and helpers.** `ErrorNotice.vue` renders any `UserMessage` (title, detail, the issues link as an anchor with `target="_blank"` and `rel="noopener"`) and shows an action button only where the parent provides a handler (`copy-diagnostics` is built in); `NotFoundState.vue` for a route without a screen or a missing record. `useModal(open, afterClose)` returns the `content` props for a Nuxt UI `Modal` or `Slideover`: `aria-modal="true"`; while open the surface's frame is `inert` (Reka UI's `hideOthers` only sets `aria-hidden`); the initial focus on the element marked `data-autofocus`; Reka's return to the trigger is prevented and `afterClose` decides where the focus goes, because the trigger may be gone. `useDelayed(source)` turns true once `source` has been true for 300 ms (`LOADING_DELAY_MS`), so a quick load shows no skeleton.
- [ ] **8. Accessibility rules every component follows** (WCAG 2.2 AA 2.4.3, 3.3.1, 4.1.3): a control that may hold the focus when it stops working says `aria-disabled="true"` and ignores the click; it never turns `disabled`, which drops the focus to the page; Nuxt UI's `loading` disables its button, so show a spinning `i-lucide-loader-circle` instead (L30). A failure is announced (`role="alert"`) or takes the focus. A required field says `aria-required="true"`; no asterisk joins a label. State is never shown by colour alone.
- [ ] **9. Waiting in tests** (`tests/support/wait.ts`, `tests/support/preload.ts`).
  - `eventually(check)` = `vi.waitFor(check, { timeout: WAIT_BUDGET_MS, interval: 10 })` with `WAIT_BUDGET_MS = 4000`. Never a bare `vi.waitFor`, whose 1 s default failed on a loaded machine (L11). A wait that succeeds returns at once; the budget stays under the 5 s test timeout, so a wait that never succeeds fails with its own assertion.
  - Wait on a condition, not a guess: a handle that settles (the settings tab double's `pending`), a count that proves the work ran. A timer only to prove that nothing happens.
  - `preloadSurface()` imports `./mount` and everything `appSurface` loads lazily (start screen, context, every section's component and badge); each test file that opens a view awaits it once at its top (L12). The first mount used to spend seconds of transform under load inside its own timeout.
  - fast-check runs with random seeds. A failure prints seed and path; replay with `assert(property(…), { seed, path })`, fix the cause, remove the options, keep the counterexample as an `examples` entry or a plain test. Never catch around an `assert(property(…))`.

## Done when

`npm run verify` exits 0; the head test fails with `noHeadPlugins()` removed from `sharedConfig` and passes with it (Task 08's discriminating check); `host.test.ts` fails when `host.ts` re-exports `mountSurface` and passes without. Commit `feat: lazy surface and runtime bridge`.

**Proven in the source repository:** the tests named above; `tests/unit/application/shell/settings-interruption.test.ts` with the group *useCommand after the scope ended* in `tests/dom/presentation/shell/use-command.test.ts`; in Obsidian `tests/e2e/specs/popout.e2e.ts` and `no-network.e2e.ts` (Task 12). Measured once in Node 24 on the built `main.js` with a stubbed `obsidian` and `document` (not an Obsidian startup number): the median `require` time fell from 43 to 38 ms with the lazy surface. **Kept without a user there:** `useQuery` and `useAppEvents` (owner decision; PBI-62).
