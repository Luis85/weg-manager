# Task 06 · Service graph, adapters, runtime

Phase A. Needs: Task 05.

**Goal.** Every application service of one plugin load is built in one place from the host's adapters. The plugin, the browser harness and the tests pass different adapters into the same graph, so the services they run are the same (Twelve-Factor X). Host events reach the application through one typed bus.

## Files

Create: `src/application/app-services.ts` (`AppServices`, `AppRuntime`), `src/application/app-services-layer.ts` (`AppAdapters`, `appServicesLayer`), `src/application/events.ts` (`AppEvent`), `src/application/shell/{event-bus,events}.ts`, `src/infrastructure/runtime.ts` (`makeRuntime`), `src/infrastructure/logging/{console-sink,incidents}.ts`, `src/infrastructure/obsidian/app-layer.ts` (`appLayer`), `src/infrastructure/obsidian/shell/{layers,notices,language,events,index}.ts`, `tests/support/adapters.ts` (`testAdapters`), `tests/support/runtime.ts` (`testRuntime`). Tests: `tests/unit/application/app-services-layer.test.ts`, `tests/unit/application/shell/event-bus.test.ts`, `tests/unit/infrastructure/logging.test.ts`, `tests/dom/infrastructure/shell/layers.test.ts`, `tests/dom/infrastructure/shell/events.test.ts`, `tests/dom/infrastructure/runtime.test.ts`. Modify: `src/application/commands.ts` (`AppServices` in `AppCommand`), `configs/fallow.config.mjs` (the zones `adapters` and `infrastructure`, the rules `adapters`, `infrastructure` and `adapters/shell` without `presentation/shell`, which follows in Task 09; Task 03 table), then `npm run fallow:config`.

## Steps

- [ ] **1. `AppAdapters`**: one adapter Layer per port, as plain fields: `settingsStore`, `notifier`, `clipboard`, `hostInfo`, `incidents`, `logSink`, and `hostEvents: Layer<never, never, ShellServices>`. Task 13 adds `noteStore` (built on the shell's services, so the in-memory store can publish its writes on the bus), `idGenerator`, `noteOpener`; a per-device store adds `deviceStore`. A new port is one field here, and each host fails typecheck until it supplies it.
- [ ] **2. `appServicesLayer(adapters, options)`**, typed `Layer.Layer<AppServices>`, in this order:
  1. the ports merged with `messagesLayer(options.language)`;
  2. `SettingsServiceLive` on them, then `LoggerLive(options)` on the settings with the `logSink` adapter, merged with `EventBusLive`: the shell's services;
  3. (Task 16) the note index on the `noteStore`, `idGenerator` and `noteOpener` adapters over the shell;
  4. `servicesLayerOf(APP_MODULES, notes)` (add `services` to `ModuleManifest` and the helper to `module.ts`), the feature modules' Layers folded onto the core services in `APP_MODULES` order: each module's Layer is built on the core services and on every earlier module's (`Layer.provideMerge` on the fold so far), so a feature service may use an earlier feature's service, and a service that needs one only a later module builds stays among the Layer's requirements and fails the type `Layer<AppServices>` (a test in `tests/unit/application/module.test.ts` folds two sample modules, the second using the first's service);
  5. `adapters.hostEvents` **last**, so a service that subscribes while it is built (the index of Task 16) sees `LayoutReady` and `VaultReady`, which the adapter may publish while it is built itself.
  `AppServices = ShellServices | NotesServices | ServicesOf<AppModule>` (no `NotesServices` before Task 13 or without Phase B); `AppRuntime = ManagedRuntime.ManagedRuntime<AppServices, never>`. A feature service that needs a service built after it fails typecheck in this one file. Replace `ShellServices` with `AppServices` in `AppCommand` (Task 05). Test: `tests/unit/application/app-services-layer.test.ts` (the order, the language, the log level).
- [ ] **3. `makeRuntime(layer)`** = `ManagedRuntime.make(layer)` (`src/infrastructure/runtime.ts`). The runtime builds its Layers on first use; `dispose()` releases every service. One runtime per plugin load; no module-level mutable state anywhere in `src/` (global constraint 11).
- [ ] **4. The event bus** (`src/application/shell/event-bus.ts`). `EventBus` with `publish(event)` and `subscribe`, which subscribes at once and returns the stream of every later event, for forked consumers that must not miss what is published right after. Backed by an **unbounded** `PubSub` acquired with `acquireRelease`: Obsidian's callbacks are synchronous, so a producer cannot wait for back-pressure, and a dropping or sliding PubSub would lose file events during a bulk sync. Shutting the PubSub down when the runtime is disposed ends every stream. `AppEvent` (`src/application/events.ts`) is `Data.TaggedEnum` of plain, serialisable data composed from the modules' event records (`ShellEvents` in `src/application/shell/events.ts`, now with the one member `LayoutReady: Record<never, never>`); consumers switch on `_tag`. Build `events`, `on(tag)` or an event only with its first consumer (L21).
- [ ] **5. The shell's host events** (`hostEventsLayer(plugin)`, `src/infrastructure/obsidian/shell/events.ts`). It publishes **nothing until `workspace.onLayoutReady`**, then `LayoutReady {}`, once per load. A feature that needs the file list reads it after `LayoutReady` instead of replaying the startup `create` flood. Rules, which also hold for the file events Task 13 adds:
  - every listener is registered with `on`, removed with `offref` in the scope's finalizer (so `runtime.dispose()` removes it whatever way the load ended, also after a failed or aborted bootstrap) **and** passed to `plugin.registerEvent` (so `unload()` detaches it synchronously before the asynchronous dispose finishes; a second `offref` is a no-op);
  - the `onLayoutReady` callback cannot be cancelled, so it checks that its scope is still open;
  - mapping and publishing run synchronously inside Obsidian's callback (`Effect.runSyncExitWith`); a defect goes to `reportDefect` and never throws into Obsidian; single events are not logged.
  The file events (`vault` `create`, `modify`, `delete`, `rename` and `metadataCache` `changed`) come in Task 13 with the store that must publish the same events; without Phase B, build only the events a feature consumes. Tests (`tests/dom/infrastructure/shell/events.test.ts`, with the double's `markLayoutReady`): nothing before layout ready, `LayoutReady` once, nothing after dispose, and a layout-ready callback that arrives after dispose publishes nothing.
- [ ] **6. The Obsidian adapters of the shell** (`shellAdapters(plugin)`, `src/infrastructure/obsidian/shell/layers.ts`): `SettingsStore` over `plugin.loadData`/`saveData` (a rejection becomes `StorageError`), `Notifier` rendering a `UserMessage` as one `Notice` (`notices.ts`: title bold, detail below, the issues link as a `createEl("a")` with `target="_blank"` and `rel="noopener"`, longer for errors than for info; no `innerHTML`), `Clipboard` over `navigator.clipboard.writeText`, `HostInfo` with `plugin.manifest.version`, `apiVersion` and the platform name read **app flags first** (`isIosApp`, `isAndroidApp`, then `isMacOS`, `isWin`, `isLinux`; L24), `incidentsLayer`, `consoleSinkLayer`, `hostEventsLayer(plugin)`. `hostLanguage()` (`language.ts`) is the only caller of `getLanguage()`, read once per load. `appLayer(plugin, options)` (`src/infrastructure/obsidian/app-layer.ts`) = `appServicesLayer({ ...shellAdapters(plugin) }, options)`; Task 13 adds `...notesAdapters(plugin)`.
- [ ] **7. Logging infrastructure.** `consoleSink` (`src/infrastructure/logging/console-sink.ts`, the only `console` use in shipped code) prefixes `[<plugin-id>]` and writes `info` through `console.debug`, because Obsidian's guidelines allow only `warn`, `error` and `debug`. `incidentsLayer`: six characters from `0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ` through Effect `Random` (not cryptographic; they only correlate a notice with a log entry). Test: `tests/unit/infrastructure/logging.test.ts`.
- [ ] **8. Test adapters and runtime.** `tests/support/adapters.ts`: `testAdapters(options)` gives an in-memory adapter for every field of `AppAdapters` (the settings store of Task 05, a recording notifier and clipboard, `testHostInfo`, sequential incidents, a recording log sink, no host event adapter unless `hostEvents` is given) and handles to them; a new port adds its in-memory adapter here once. `tests/support/layers.ts` adds `recordingEventBus()` (the real bus recording every event, with `failNextPublish`), `testMessages` and `controllableRead(initial)`: an effect `read` that gives a number or fails with `VaultReadError` (`initial` is a number or `"fail"`), with `hold()`, `release()`, `held()` and `set(next)`, for the composables' tests of Task 09. `tests/support/runtime.ts`: `testRuntime(options)` builds the plugin's own graph (`appServicesLayer` over `testAdapters`, `language: options.language ?? "<test-language>"`) in development mode so the sink sees every level, and returns `runtime` with the handles `store`, `notifier`, `clipboard`, `logger`, `source` (`controllableRead(options.source ?? 3)`) and, from Task 13 and 16, `notes` and `vaultReady()`.
- [ ] **9. Runtime test on the double** (`tests/dom/infrastructure/runtime.test.ts`): `makeRuntime(appLayer(plugin, options))` runs a shell use case against the Obsidian adapters on the double; after `dispose()` running an effect rejects.
